# BayarLab 0.1.0 — release notes (draft)

**Status:** release candidate; not published. **Release date:** pending release approval.

BayarLab is a local-first simulator for exercising payment webhook receivers with synthetic provider-shaped events. It does not create payments, contact payment gateways, or require live credentials.

## Included

- Midtrans Classic: BNI virtual-account pending, settlement, cancellation and expiry; selected accepted credit-card capture and decline fixtures.
- Xendit Payments API v3 Indonesia DANA: capture and a clearly labelled composed failure fixture.
- DOKU Direct API non-SNAP Mandiri virtual-account success.
- CLI send, offline inspection, duplicate/replay, bounded chaos experiments, YAML scenario assertions, and `text`/`json`/JUnit reports.
- Loopback-only dashboard with redacted display and byte-preserving same-target replay.
- Standalone `bayarlab` CLI package, dashboard assets, and MIT license.

## Install after publication

Node.js 22.13.0 or newer is required.

```bash
npm install --global bayarlab@0.1.0
bayarlab --help
```

Before registry publication, follow the repository's local tarball steps in the README instead. The package name and version must be checked against the registry at release time.

## Scope and limitations

All events are synthetic. Provider payload fidelity is limited to the documented profiles and fixtures in the provider matrix. No captured sandbox callbacks are included. Do not point the tool at production endpoints or use production keys. The dashboard listens only on loopback. See the [security policy](../../SECURITY.md), [provider matrix](../provider-matrix.md), and [release candidate audit](../release-candidate-audit.md).
